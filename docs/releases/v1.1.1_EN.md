# rj-grid v1.1.1 Release Notes (English / GitHub & npm text archive)

> Archived copy of the public release text for v1.1.1; the Chinese version is [v1.1.1.md](https://gitee.com/rjding/rj-grid/blob/master/docs/releases/v1.1.1.md).
> Date: 2026-10-15 · Tag: `v1.1.1` · npm: `rj-grid@1.1.1`

A zero-dependency Vue 3 virtual grid. This release adds **host-defined extra fields** to the import dialog shipped in v1.1.0 (`importExtraFields`), so an "overwrite existing" switch can finally live inside the import dialog instead of a second confirmation popup.

## ✨ New: extra fields inside the import dialog (`importExtraFields`)

Declare an array of fields and they appear in a "3. Import options" section inside the dialog (under the file picker, above the submit button). When you click "Import", the current value of every field arrives in the **second argument** `extras` of `importFile`.

```vue
<template>
  <rj-grid
    ref="gridRef" :columns="cols" :rows="rows" row-key="id"
    show-import :import-file="onImportFile" :import-extra-fields="extraFields"
  />
</template>

<script setup lang="ts">
import type { RjImportExtraField } from 'rj-grid'

const extraFields: RjImportExtraField[] = [
  { key: 'updateSupport', label: 'Update existing rows (non-empty cells only)', kind: 'checkbox', defaultValue: false },
  {
    key: 'ownerDept', label: 'Owning department', kind: 'select', defaultValue: 'WH',
    options: [{ value: 'WH', label: 'Warehouse' }, { value: 'QC', label: 'Quality' }],
    tip: 'Decides which department owns these rows on the backend',
  },
]

async function onImportFile(file: File, extras: Record<string, unknown>) {
  const form = new FormData()
  form.append('file', file)
  form.append('updateSupport', String(!!extras.updateSupport)) // the checkbox value (boolean)
  form.append('ownerDept', String(extras.ownerDept ?? '')) // the select's value, not its caption
  await importItem(form)
  gridRef.value?.refresh()
}
</script>
```

The field shape (`RjImportExtraField`):

| Key | Meaning |
|---|---|
| `key` | unique id, used as the key in the `extras` object |
| `label` | the caption — **yours to own** (the component does not translate it; feed zh/en text yourself alongside `locale`) |
| `kind` | `'checkbox'` \| `'select'` — those two widgets and nothing else |
| `defaultValue` | initial value: `false` for a checkbox, `undefined` for a select when omitted |
| `options` | candidates for `kind: 'select'`, `{ value, label }`, the same structure as a column editor dropdown |
| `tip` | a small helper line under the label |

The grid keeps its old "no business logic in the grid" contract: it only renders the fields and reports the values back. The widgets are a native checkbox and a native `<select>` (the same family as the row-form dialog — no UI library dependency, and no popup layer clipped by the dialog). While the upload is running the whole dialog body is inert, fields included; a rejected `importFile` keeps the dialog open **without losing the field values**; reopening the dialog resets them to `defaultValue`; and **with no fields declared the section never renders — the dialog looks exactly like v1.1.0**.

## 🔧 Fix along the way

The import dialog now has a height cap (`max-height: 82vh` with its middle section scrolling, the same recipe as the row-form dialog). Before this, many host fields or a short viewport (≲440px) grew the dialog until its header and its "Cancel / Import" footer were clipped with no way to scroll; now the footer stays put, the body scrolls on its own, and scrolling content no longer pokes past the rounded corners.

## 📦 Upgrading to 1.1.1

**No breaking changes**; v1.1.0 code keeps working as-is:

- `importFile`'s type grew from `(file: File)` to `(file: File, extras: Record<string, unknown>)`. In TypeScript a function with fewer parameters is assignable to a type with more, so an existing `function onImportFile(file: File)` **needs no edit** and still type-checks.
- The only new prop is `importExtraFields` (default `[]`); omit it and the dialog is unchanged.
- In `extras`, a select carries its `value`, not its caption; unselected or undeclared fields are `undefined`, so coerce before building your payload.

This is a purely additive capability (which semver would allow as a minor bump); since it completes the same import flow shipped in v1.1.0, it is released as the patch number `1.1.1`.
