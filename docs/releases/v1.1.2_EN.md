# rj-grid v1.1.2 Release Notes (English / GitHub & npm text archive)

> Archived copy of the public release text for v1.1.2; the Chinese version is [v1.1.2.md](https://gitee.com/rjding/rj-grid/blob/master/docs/releases/v1.1.2.md).
> Date: 2026-11-04 · Tag: `v1.1.2` · npm: `rj-grid@1.1.2`

A zero-dependency Vue 3 virtual grid. This release is about **smoother interactions** and **big lists that stop jumping around**: the pin now swaps left/right freezing in one click; grouping under pagination/infinite **no longer bothers the backend**; the `select` header filter can be searched **by its display label**; and `applyTransaction.replaceAll` lets hosts drop the `gridKey++` full rebuild.

## ✨ Pin three-state cycle: swap left/right freezing in one click

The 📌 in the tool panel's "columns" manager and in the column menu's "columns" tab changed from two states (pin left / unpin) to a **three-state cycle**:

```
unpinned → pin left → pin right → unpinned → …
```

One click moves the column one step around the cycle, so switching between left and right freezing no longer takes a detour. The column menu's "general" tab still offers the **precise** left/right entries; both paths share the same column state, so they never fight.

```vue
<rj-grid :columns="cols" :rows="rows" row-key="id" show-toolbar />
```

- The pin's `title` follows the state: "click to pin right / click to unpin / click to pin left".
- The emoji pin does not take CSS color, so state is conveyed by "grayscale + azimuth tag + title", readable in both light and dark themes.

## ✨ Pagination / infinite: grouping is local to the loaded page

Under `data-mode="pagination"` or `"infinite"`, dragging a column into or out of the group bar now only groups the **rows already loaded for the current page**:

- it **never triggers `loadData`**, never jumps back to page 1, and never resets scroll;
- grouping travels on its own `rowGroup` channel and is **not mixed into `sort` / `filters`** to pollute the query;
- only `serverSide` (SSRM) or an explicit `serverSideGrouping` re-fetches from the backend by grouping.

```vue
<!-- Pagination + page-local grouping: simply omit server-side-grouping -->
<rj-grid
  :columns="cols" data-mode="pagination" :load-data="loadData" :page-size="50"
  row-key="id" groupable show-group-panel
/>
```

> If you really do want "grouping pushed to the backend", add `server-side-grouping` explicitly and the behavior is the same as before (re-fetch by grouping).

## ✨ select header filter: search matches both value and label

The candidate search for `filter: 'select'` now **matches both the raw value and the display label**. For a dict column (value is a code, label is text, e.g. `{ 1: 'East' }`) typing the label directly finds it, and you no longer see "no options" when options clearly exist.

```ts
const cols = [
  { field: 'region', title: 'Region', filter: 'select', dict: 'regionTree' },
]
```

> Multi-select, select-all and exclude-selected (`in` / `notIn`) are unchanged; this release only broadens the search.

## ✨ applyTransaction.replaceAll: whole-page / full replace

`RjTransaction` gains `replaceAll`. Under `pagination` / `infinite`, after re-fetching the current page it **replaces the loaded set in one shot**:

- row identity is matched by `rowKey`, so **selection is preserved**;
- the **component is not rebuilt**, so scroll position and the pager/page number are kept;
- under SSRM it is ignored (the block cache is server-authoritative; keep using `refreshServerSide`).

```ts
// Old: full rebuild (loses column width / scroll / view state, flashes)
function reload() { gridKey.value++ }

// New: re-fetch the current page and replace, without rebuilding
async function reload() {
  const res = await fetchPage(currentPage.value, pageSize.value) // your fetch
  gridRef.value?.applyTransaction({ replaceAll: res.list })
}
```

> Note: `remove` in `applyTransaction` is still a no-op under the pagination branch; for deletes use `replaceAll` to back-fill, or `update`. When reconciling with the server, `replaceAll` is the safer entry point.

## 📦 Upgrading to 1.1.2

**No breaking changes**; v1.1.1 code keeps working as-is. There is one **behavior change**:

- Under `pagination` / `infinite`, dragging a column into or out of grouping **no longer** triggers a backend re-fetch or a jump to page 1. If your page relied on "grouping, then the backend returns group rows", turn on `serverSideGrouping` explicitly.
- `RjTransaction.replaceAll` is new and optional; omit it and everything stays the same.
