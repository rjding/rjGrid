# rj-grid v1.1.0 Release Notes (English / GitHub & npm text archive)

> Archived copy of the public release text for v1.1.0; the Chinese version is [v1.1.0.md](https://gitee.com/rjding/rj-grid/blob/master/docs/releases/v1.1.0.md).
> Date: 2026-10-15 · Tag: `v1.1.0` · npm: `rj-grid@1.1.0`

A zero-dependency Vue 3 virtual grid. This release adds **toolbar Excel import** plus three interaction/visual fixes.

## ✨ New: importing Excel (`showImport`)

The toolbar "Import" button is **hidden by default** — importing writes into your backend, so it should only appear once you wire a callback up, and it ignores the `exportable` switch. It sits at the far left of the same group as Print / CSV / PDF / Excel.

Clicking it opens the built-in import dialog with a two-step flow: **① download the template → ② pick (or drag) an Excel file → "Import"**.

- **The component never parses the Excel and never touches the API**: it hands your picked `File` over as-is to the `importFile` callback, so which columns the backend expects and which endpoint it calls stays entirely yours (the same "no business logic in the grid" contract as `serverExport`).
- **Two template sources**: omit `importTemplate` and the component builds an xlsx header template from the **columns visible on screen** (export it, edit it, import it back — the column order already matches); or pass a download URL, or a function returning `res.blob()` and let the component save the backend stream.
- **Failures stay recoverable**: only `.xlsx` / `.xls` are accepted; a wrong type, no file picked and an upload in progress each get their own clear state. If `importFile` rejects, the dialog stays open and **shows the backend's reason in red inline** (not a toast — the modal overlay would cover it), so you can just pick another file; a success closes it.
- All dialog text goes through i18n (zh/en, follows the theme language) and any key can be overridden via `localeText`.

```vue
<template>
  <rj-grid
    ref="gridRef" :columns="cols" :rows="rows" row-key="id"
    show-import :import-file="onImportFile" import-template="/wms/item/importTemplate"
  />
</template>

<script setup lang="ts">
async function onImportFile(file: File) {
  const form = new FormData()
  form.append('file', file)
  const res = await importItem(form)
  if (res.code !== 0) throw new Error(res.msg) // throwing keeps the dialog open and shows the reason in red
  gridRef.value?.refresh() // re-fetch after a successful import
}
</script>
```

New props at a glance:

| Prop | Default | Description |
|---|---|---|
| `showImport` | `false` | toolbar "Import" button visibility; not governed by `exportable` |
| `importFile` | `-` | `(file: File) => void \| Promise<void>`; rejecting keeps the dialog open for a retry, resolving closes it |
| `importTemplate` | `-` | a template URL, or `() => string \| Blob \| void \| Promise<...>`; omit it and the component generates one from the visible columns |

Full parameters in [Manual §9.6](../RjGrid_Manual_EN.md) and the "⬆ Importing Excel" section of the README.

## 🐞 Fixes

- The query bar "Reset" button now also **clears the selected rows / range**, instead of leaving the highlight behind.
- Action-column (`actions`) visuals: button spacing and the right divider no longer misalign inside frozen columns.
- Data-row bottom borders no longer disappear under custom row coloring / merged cells.

## 📦 Upgrading to 1.1.0

The version jumps from 0.3.5 to 1.1.0 (**past 1.0**), so projects pinned to `"rj-grid": "^0.3.5"` **will not receive 1.x automatically** (a caret on 0.x only locks to the minor). Bump it explicitly:

```jsonc
{ "dependencies": { "rj-grid": "^1.1.0" } }
```

There are **no breaking changes** — the API is identical to 0.3.5; reinstall and you're done.
