# rj-grid v1.1.3 Release Notes (English / GitHub & npm text archive)

> Archived copy of the public release text for v1.1.3; the Chinese version is [v1.1.3.md](https://gitee.com/rjding/rj-grid/blob/master/docs/releases/v1.1.3.md).
> Date: 2026-11-05 · Tag: `v1.1.3` · npm: `rj-grid@1.1.3`

A zero-dependency Vue 3 virtual grid. This release is two **visible correctness fixes**: the floating filter row of date/datetime columns becomes a **native date picker**; and the pivot "Grand Total" row label no longer **hides the first measure column's total**.

## ✨ Date columns: floating filter is now a native date picker

For columns typed `date` / `datetime` (or `filter: 'date'`), the floating filter row under the header switches from a text input to a **native date picker** (`<input type="date">`); picking a day filters by "same day":

```vue
<rj-grid :columns="cols" :rows="rows" row-key="id" floating-filters />
```

```ts
const cols = [
  { field: 'createTime', title: 'Created At', type: 'datetime', width: 160 },
]
```

- **Same semantics as the header funnel and the cell editor**: `date` compares by day; `datetime` takes the date part and compares by day (every moment of that day matches).
- **Fallback**: if the column already holds range/operator text (`2024-01-01~2024-02-01`, `>=2024-01-01` — e.g. restored from an older version or from `stateKey`), that column **falls back to a text input** showing the raw value, so you never get "filtering is active but the control looks empty".
- Range and operator expressions still live in the header funnel — no capability was removed.
- Other column types (text / number / select) keep their plain inputs.

## ✨ Pivot total row: the label no longer eats the first measure column

Before: with a pivot configured and **no row grouping**, the pivot result is a single "Grand Total" row, and group-row labels are drawn on the *first non-control column* — which happened to be the **first pivot measure column**. So `Total (N)` replaced that column's total entirely: "the total field hides the first value".

After: when there are no row dimensions the engine generates a **dedicated row-label column** (header "Grand Total", 120px wide) to host the label, leaving **every measure column to itself**:

```
□ │ ⠿ │ Grand Total(8000) │ ¥266.43 │ ¥794.85 │ ¥59.92 │ …
          ↑ label column    ↑ M-10000  ← previously "Total(8000)" sat here; ¥266.43 was gone
```

- With row dimensions nothing changes: row-dim columns lead and the total row label lands on the row-dim column.
- **Old persisted state self-heals**: an existing `state-key` has no such column, so it used to be registered at the end of the column order and pushed the label to the far right. The engine now always ranks row-label columns right after the control columns and before measure columns — both layout and persisted state converge; no need to click "Reset".
- The "Grand Total" column exports its label value, matching what is on screen.

## 📦 Upgrading to 1.1.3

**No breaking changes** — v1.1.2 usage keeps working. Two **visual/interaction** changes:

- The floating filter row of date/datetime columns is a date picker now. If your page relied on typing `>=2024-01-01` / `a~b` into that row, use the header funnel instead (`api.setFilter` works the same), or keep the column's old text value (the component falls back to a text input automatically).
- A pivot table without row grouping gains **one more column** (the "Grand Total" label column). If the host hard-codes column counts (e.g. computing width from `gridColumns.length`), account for "+1".
